## SableStart CodeQL

Active workflow:

```text
packages_apps_SableStart/.github/workflows/codeql.yml
```

Properties:

- GitHub-hosted Ubuntu 22.04 only;
- push, pull request, weekly schedule, and manual trigger;
- detects Java/Kotlin source before analysis;
- CodeQL Java/Kotlin `build-mode: none` so it does not require the AOSP/Soong tree;
- `contents: read`, `actions: read`, and `security-events: write` only for the analysis job;
- GitHub Actions pinned to full commit SHAs.

A main-branch run completed successfully while the current `main` branch remained documentation/CI-only and therefore skipped code analysis after source detection. The workflow is intended to analyze Java/Kotlin when source is present in future PR/main revisions.

## SableStart MobSF source scan

Active workflow:

```text
packages_apps_SableStart/.github/workflows/mobsfscan.yml
```

It runs only on GitHub-hosted Ubuntu and detects Kotlin/Java/AndroidManifest source before invoking the SHA-pinned MobSFScan Action. SARIF upload is SHA-pinned through the CodeQL upload action.

This is source-oriented scanning only. It is not a substitute for Soong build, APK inspection, runtime permission/AppOps evidence, or Panther device qualification.

## Dependabot

GitHub Actions dependency-update configuration is active in the current organization repositories listed above. Updates are weekly, reviewable pull requests rather than silent workflow mutation.

Dependency automation does not override the requirement that executed Actions and reusable workflows remain full-SHA pinned.

## Not yet active

The following remain intentionally unimplemented/disabled:

- general self-hosted Actions execution on `sable-builder-01`;
- arbitrary PR execution on the ThinkPad;
- C2 trusted Soong/AOSP build jobs;
- C3 clean `platform_manifest` reconstruction jobs;
- C4 automated Panther deployment/runtime jobs;
- C5 release/signing automation on `sable-signer-01`;
- production signing material in GitHub or on the builder;
- branch-protection required-check enforcement.

These are enabled only after their corresponding trust boundary, scripts, runner identity, and evidence contract are ready.

## Claim boundary

Current CI activation proves that a reusable, SHA-pinned, least-privilege GitHub-hosted C1 policy framework is active and that SableStart has hosted CodeQL/MobSF workflow definitions. It does not prove SableStart compilation, AOSP reconstruction, device behavior, reproducibility, or release-signing correctness.
