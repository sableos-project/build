# R8 B1 command reference

Status: **implementation reference; the normative gate is `R8_PREIMAGE_GATE.md`.**

This file records representative commands for the first `ai-g732` B1 run. Exact paths/targets must be resolved from the active Android 17 / GrapheneOS tree before use.

## Authorization classes

```text
READ_ONLY_GRAPH_QUERY
  no source mutation
  no device contact
  no signing
  no clean/clobber/delete

NARROW_BUILD
  build/output mutation only
  separately authorized

NO_DEPS_REPACKAGE
  output/image mutation only
  separately authorized
  never dependency-closure proof
```

## 1. Generate graph

Typical graph-generation command after the exact lunch/product/release/variant and OUT_DIR are bound:

```bash
m nothing
```

This mutates generated build output and therefore belongs to an authorized B1 build-output phase, even though it does not compile the broad product.

## 2. Discover combined Ninja graph

Do not assume a path without checking the active tree. Once resolved:

```bash
NINJA=prebuilts/build-tools/linux-x86/bin/ninja
COMBINED_NINJA="$OUT_DIR/combined-${TARGET_PRODUCT}.ninja"
MODULE=SableCalculator
```

## 3. Query module/target edge

```bash
"$NINJA" -f "$COMBINED_NINJA" -t query "$MODULE"
```

If the module name is not itself a Ninja target in the exact tree, first derive the concrete installed/intermediate target and query that target instead. Do not treat a failed guessed module-name query as proof the Soong module is absent.

## 4. Query hard inputs

Where supported by the bundled Ninja:

```bash
"$NINJA" -f "$COMBINED_NINJA" -t inputs "$MODULE"
```

Use this to prove the frozen A2 APK path participates in the graph. Preserve the exact output as evidence.

## 5. Java/Soong dependency metadata

When generated by the target tree:

```bash
find "$OUT_DIR" -name module_bp_java_deps.json -print
```

Inspect the matching module dependency entry. This is dependency evidence only; it does not prove product selection or image membership.

## 6. Dexpreopt / uses-library metadata

Discover rather than guess paths:

```bash
find "$OUT_DIR/soong/.intermediates" -type f -name dexpreopt.config -print
```

For the imported module record:

```text
uses_libs
optional_uses_libs
enforcement state
class-loader context / library paths where represented
dexpreopt enabled/disabled state
```

Do not require nonexistent properties such as `dex_preopt.copy_files` unless the exact target-tree schema actually defines them.

## 7. Narrow module build

Only after ordinary A1/A2 application failures are already closed:

```bash
m "$MODULE"
```

This proves only the module/import build boundary and its generated outputs. It does not by itself prove PRODUCT_PACKAGES selection.

## 8. PRODUCT_OUT proof

Resolve `$ANDROID_PRODUCT_OUT` from the active build environment and inspect the exact expected install path, for example:

```bash
find "$ANDROID_PRODUCT_OUT" -type f -name '*.apk' -path '*Sable*' -print
sha256sum "$ANDROID_PRODUCT_OUT"/<resolved-path>/<app>.apk
```

Record the discovered path; do not hard-code `/system/app` before the module configuration proves the partition.

## 9. Optional `snod` experiment

If PRODUCT_OUT is already known current and a quick system-image repackaging experiment is specifically authorized:

```bash
m snod
```

or the target-tree equivalent.

`snod` deliberately ignores ordinary dependencies. With dexpreopt enabled, AOSP warns that a full rebuild may be needed. Therefore its result is only packaging evidence from the existing PRODUCT_OUT state.

## 10. Native artifact audit

Use the repository gate against the trusted A2 APK or discovered processed APK:

```bash
APK=/absolute/path/to/app.apk \
LLVM_READELF=/absolute/path/to/llvm-readelf \
LLVM_NM=/absolute/path/to/llvm-nm \
ZIPALIGN=/absolute/path/to/zipalign \
EVIDENCE_DIR=/tmp/SABLE_R8_APP_AUDIT_<id> \
bash gates/r8_app_artifact_audit.sh
```

The exact Android/NDK tools should come from the pinned A2/B1 toolchain rather than the host distribution for accepted evidence.

## 11. Page-size runtime evidence

After device contact is separately authorized:

```bash
adb shell getconf PAGE_SIZE || adb shell getconf PAGESIZE
adb shell getprop ro.boot.hardware.cpu.pagesize
adb shell getprop ro.product.cpu.pagesize.max
adb shell getprop ro.product.page_size
adb shell getprop ro.product.build.16k_page.enabled
```

The developer-option property does not prove the current kernel page size; `getconf`/runtime evidence does.

## 12. SELinux review

Do not create a custom policy merely because an APK is under `/system/app`.

If the application actually requires a custom app domain/seinfo/privileged capability, discover and review the exact applicable files, which may include:

```text
mac_permissions.xml
seapp_contexts
*.te
file_contexts
property_contexts
privapp-permissions XML
```

The normal R8 default is ordinary app sandboxing with no new custom domain.

## 13. Fresh-output decision

Never automate `m clean`/clobber from this reference. If incremental correctness becomes doubtful after a major Soong/toolchain/source-policy transition, preserve the current OUT_DIR and create a fresh isolated OUT_DIR when the claim requires it.
